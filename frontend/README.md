# Веб-интерфейс

Интерфейс собран на PHP и HTML/CSS, соединение с MySQL и проверка сессий выполняются сервером.

- `login.php`, `register.php`, `logout.php` — вход, регистрация и выход;
- `dashboard.php` — личный кабинет;
- `transactions.php` — список операций текущего пользователя, поиск по описанию и категории, фильтры по типу, категории и датам, выдача по 20 строк на страницу;
- `budget.php` — месячный бюджет, лимиты по категориям расходов, расчет факта и пороговые уведомления;
- `currency.php` — конвертер рублей в иностранные валюты по справочным курсам Банка России; значения кэшируются в `exchange_rates`;
- `transaction.php?id=…` — подробности операции. Пользователь видит только свои записи, администратор может открыть любую;
- `admin-transactions.php` — поиск, фильтры и список всех операций. Страница доступна только роли `admin`.

Новые регистрации получают роль `user`. Для новой установки импортируйте `database/install.sql`, затем при необходимости `database/test_data.sql` (демо-администратор: `egor.demo@example.com`, пароль `Demo123!`). Для существующей базы выполните нужные миграции из каталога `database`, включая `migrate_external_rates.sql` для таблицы валютного кэша. Назначить роль администратора можно запросом `UPDATE users SET role = 'admin' WHERE email = 'адрес';`.

Страницы операций используют параметризованные запросы и проверяют владельца записи на сервере. Ограничения поиска и фильтров применяются к SQL-запросу, а не только к отображённым строкам. Бюджет считает только завершенные расходы выбранного месяца и проверяет владельца категории перед сохранением лимита.

Интеграция курсов использует XML endpoint Банка России и обновляет кэш не чаще одного раза в 12 часов. Если сервис недоступен, приложение показывает последние сохранённые значения. PHP-предупреждения, необработанные исключения и фатальные ошибки записываются в `var/logs/application.log`; Apache запрещает читать журнал по HTTP, а сами логи исключены из Git.
